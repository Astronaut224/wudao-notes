# 性能报告

> 目标（开发说明 §5.2）：空闲 CPU 争取 <1%；常驻工作集争取 ≤150MB（含 WebView2 子进程）；
> 1000 待办 / 2000 笔记列表与搜索流畅；禁止 1 秒级定时器、轮询、常驻全表查询。

## 架构层面的性能设计

- 单进程单 WebView：正常/迷你模式复用同一窗口（resize），无多 WebView 开销
- 前端零轮询：数据刷新全部由用户操作/后端事件驱动；无 setInterval 心跳
- 单 SQLite 连接（Mutex）+ WAL：写节流（文本 650ms 防抖 + 失焦落盘）
- 列表查询走索引（status,priority,sort_order）；搜索为 LIKE（转义）+ 前端一次拉取
- 图片仅在选中详情时按需经 wudaores 协议加载，`Cache-Control: no-store`，64MB 上限
- 附件操作（复制/备份）在阻塞线程执行，不冻结 UI
- 发布构建 `opt-level="s"` + LTO + strip

## 实测数据

| 指标 | 目标 | 实测 | 备注 |
|---|---|---|---|
| 启动到可交互 | — | <2s（主观） | release exe 冷启动 |
| 主进程内存（空数据） | ≤150MB | **≈40MB** | tasklist：35–40MB（不含 WebView2 子进程，完整进程树待测） |
| 主进程内存（含 6 待办 + 3 笔记） | ≤150MB | ≈36MB | 与空数据几乎相同 |
| 1000 待办列表滚动 | 流畅 | 待测 | |
| 2000 笔记搜索 | 流畅 | 待测 | LIKE 转义查询 |
| 8 小时常驻内存增长 | 无持续增长 | 待测 | 每 30 分钟采样 |
| 空闲 CPU | <1% | 待测 | 无定时器架构，理论近似 0 |

> 初步观察：主进程常驻内存约 40MB，远低于 150MB 目标；WebView2 子进程占用需在完整测量中用
> Process Explorer 按进程树汇总后如实补充。本表不承诺未实测的数字。

## 测量方法

1. 造数脚本：Rust 侧临时命令或直接 SQL 插入 1000 todo / 2000 note。
2. CPU/内存：`Process Explorer`（进程树视图）或 `typeperf "\Process(wudao*)\% Processor Time"`。
3. 8 小时常驻：窗口隐藏到托盘，定时采样内存曲线；结束前做一次全量功能回归。

> 说明：WebView2 实际占用受系统版本与运行时影响，允许实测偏差，结果如实记录，不做无依据的轻量承诺。
